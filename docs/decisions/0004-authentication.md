# ADR-0004 — Minimal session authentication

- **Status:** ACCEPTED implementation of the owner's Milestone 4 authorization, 2026-11-02.
- **Stack:** express-session with connect-pg-simple and an explicitly migrated PostgreSQL sessions table. No JWT, in-memory session fallback, registration or password-reset workflow.
- **Passwords:** asynchronous Node scrypt; N=32768, r=8, p=3, 64-byte derived key and 16-byte random salt. Store algorithm/parameters/salt/hash, never plaintext. Timing-safe comparison. Unknown usernames perform equivalent scrypt work. Seed passwords are distinct, environment-supplied, at least 12 characters and at most 256 UTF-8 bytes. Re-seeding verifies existing identities and refuses resets or reactivation.
- **Sessions:** regenerate on login; store user ID, CSRF token and absolute eight-hour expiry. Cookie carries only signed opaque ID. HTTP-only, SameSite=Lax, host-only, Path=/; production additionally Secure and __Host- prefix. Store TTL is not extended by reads; absolute expiry is checked server-side. Logout destroys the row. Expired/disabled sessions regenerate anonymously and lose authorization. User activation and role load from DB on every authenticated request.
- **CSRF:** GET session bootstraps an anonymous session/token. Every implemented POST requires exact APP_ORIGIN and matching session-bound random token. Login rotates both session ID and CSRF token. No permissive CORS. Auth responses use Cache-Control: no-store.
- **Authorization:** estimator may reach draft creation boundary; sales head is read-only for T01. Anonymous requests get 401; wrong roles 403. Permitted draft requests return explicit 501 until the persistence milestone. No fake quotation is created, no UI draft button is shown, and no quote table is added here.
- **Abuse limits:** 10 login requests per IP per 15 minutes, including successful attempts, enforced before JSON parsing/session/hash work. express-rate-limit's process-local store is appropriate for one instance only; restart clears counters. Shared limiting is required before horizontal scaling. JSON body limit 4 KiB; password input limit 256 bytes.
- **Proxy/TLS:** production APP_ORIGIN must be HTTPS. TRUST_PROXY_HOPS defaults to 0; set 1 only behind one trusted reverse proxy with direct app access blocked and forwarded headers sanitized. Untrusted forwarded-proto headers do not enable secure cookies.
- **Database access:** local forgequote_app owns newly created auth tables but older tables retain their owners. Before deployment provision non-owner runtime credentials: SELECT users; SELECT/INSERT/UPDATE/DELETE sessions; business permissions by milestone. Migration/seed credentials remain separate. Runtime must not update hashes or activation flags.
- **Trade-offs:** no MFA, recovery, user management, all-device logout, or shared rate limiting. Eight-hour sessions require re-login after expiry. PostgreSQL failure blocks authentication visibly (503); no fallback. Anonymous CSRF sessions expire and are pruned periodically.
