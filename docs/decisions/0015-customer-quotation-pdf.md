# ADR-0015 - Issued customer PDF from an allowlisted saved snapshot

Status: ACCEPTED under explicit owner T05 implementation authorization, 2026-11-05. Financial contract v0.2 and lifecycle ADR-0014 unchanged. No database migration or lifecycle event added.

## Eligibility and snapshot consistency

GET /api/quote-versions/:id/pdf requires a current authenticated active estimator or Sales Head. This preserves the accepted two-role synthetic-demo read scope; there is no public/customer-token endpoint. The service rechecks activation/role and locks the quotation header FOR SHARE, serializing with the unchanged header updates used by version creation. Concurrent downloads may share the lock. The existing snapshot and lifecycle readers accept an optional server-only shared client, matching the established service-composition pattern; their standalone behavior and all write paths are unchanged.

Within that transaction, read the exact immutable version and event history, require lifecycle status issued, its matching version-bound issued event/quotation number, and not stale. Assemble the PDF buffer before releasing the lock. A newer version committed before lock acquisition makes the request stale and blocks the final PDF; a new version after the completed authorized read does not retroactively retract a downloaded document. Older issued events/snapshots remain immutable and readable through existing endpoints, but this final-download endpoint deliberately denies superseded versions as requested for T05. There is no draft preview or alternative bypass query parameter.

## Customer confidentiality and presentation

An explicit object allowlist projects only customer name, RFQ reference, quotation number, exact version ID/number, issue timestamp, pricing date, saved GST percentage and three saved scenario arrays. Each line contains part number, description, annual quantity, selling unit price excluding GST and stored taxable line total. Each scenario contains its stored quotation subtotal/GST/total. No material/machine rates, cost lines, margins, routing/setup inputs, rate/version provenance, actors, decision reasons or internal JSON/attachments enter the PDF renderer or metadata. The exact quotation version ID is required customer document provenance; internal rate-version IDs are excluded.

The renderer formats decimal strings directly with Indian digit grouping and two saved paise places. It never converts money to Number, recomputes rates/taxes/prices, sums scenario amounts, infers quantities or substitutes zeros. Missing/malformed saved values fail. The 50/100/150 labels identify separate stored annual-volume alternatives; the 100% scenario is explicitly baseline. GST is labeled illustrative consistently with the accepted product. Issue date is the issued event timestamp in Asia/Kolkata; pricing date is the saved date-only value. No fabricated address, GSTIN, signature, validity period or payment term.

A4 portrait, branded header, wrapped component cells, right-aligned numeric columns, alternating rows, repeated continuation headers, intact rows/totals blocks and exact-version/Page X of Y footers. Font metrics determine row height and pagination, including unbroken identifiers and large financial strings. Footer text is outside body flow to avoid extra blank pages.

## Libraries, fonts and operational tradeoffs

Pinned PDFKit 0.20.2 (MIT) and fontkit 2.0.4 (MIT), both pure Node libraries. The explicit fontkit dependency uses PDFKit's existing parser version and checks glyph coverage before output, preventing silent missing-character boxes. Official PDFKit documentation: https://pdfkit.org/docs/getting_started.html and https://pdfkit.org/docs/text.html ; release source: https://github.com/foliojs/pdfkit/releases . No headless browser, Python, office tool, system font or external rendering service is required by the API.

Unmodified Noto Sans Regular/Bold TTFs are bundled in apps/api/assets/fonts under SIL OFL 1.1. Full copyright/license and source URLs/SHA-256 hashes accompany them. Official license: https://github.com/notofonts/noto-fonts/blob/main/LICENSE . The license permits embedding/redistribution with its required notices. Subsets are embedded, including Unicode U+20B9. This pair supports Latin/Greek/Cyrillic and rupee; unsupported scripts/symbols return an explicit 422 rather than altered customer text or fallback boxes. Broader script coverage needs separate licensed fonts/tests.

PDF.js 6.5.438 (Apache-2.0, Node 24 compatible) is a root dev dependency for independent content/geometry/font/attachment checks: https://github.com/mozilla/pdf.js . Its optional canvas support and an ignored local PDFium test tool were used for raster QA only. Neither is imported by production application code. Renderer artifacts remain ignored test output, not production stored files.

The response is fully assembled before headers, application/pdf, attachment filename from the constrained stored quotation number, no-store, nosniff. Browser uses authenticated fetch/blob download and displays failures without pretending success. New process-local limit: 20 PDF requests/actor/15 minutes, including denied attempts after authentication. The existing quotation-write limiter/CSRF/Origin/idempotency rules are untouched. PDF buffers are limited to 4 MiB and explicit layout to 40 pages; 1-20 components/scenario match the accepted UI/service bounds. A large unsupported snapshot fails visibly rather than truncating or recalculating it. No PDF cache or filesystem writes in runtime, no PDF byte persistence/digital signature or PDF/A claim.

Downloads hold a header read lock through generation: simple consistent authorization at modest demo scale, but new calculations can wait while a PDF is assembled. No worker pool/distributed rate limiter added. Existing trusted runtime credentials/maintenance-owner and multi-tenant limits persist. Render/Neon compatibility is established by local Node 24 build/startup and pure Node rendering, not a cloud deployment claim.
