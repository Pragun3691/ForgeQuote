# Deployment preparation — not deployed

Same-origin build: `npm ci`, `npm run build`, then `npm start`. Express serves Vite assets and `/api` on the platform's PORT. Set DATABASE_URL, NODE_ENV=production, DEMO_GST_PERCENT=18, random SESSION_SECRET and actual HTTPS APP_ORIGIN (no trailing slash). Configure TRUST_PROXY_HOPS=1 only behind one trusted reverse proxy, with direct app access blocked; otherwise leave 0. Never put secrets in frontend assets. Run migrations with maintenance credentials; seed synthetic RFQ and users separately. Seed passwords are environment variables used only by db:seed-users and are not needed in the runtime environment.

No services purchased or deployed. Auth APIs and independent authorization middleware are tested; there is no quotation-creation endpoint or quote-write test yet. Migrations/seeds require a separate maintenance role through MIGRATION_DATABASE_URL (never runtime fallback); omit that URL from deployed API settings. Current ordinary runtime grants are users/history/business/ledger SELECT and sessions CRUD. Existing forgequote_app database/auth-table ownership is preserved per instruction; owner DDL/self-grant powers remain and block full runtime isolation before public deployment. Resolving ownership/provisioning needs separate authorization. Session errors return 503; no in-memory fallback.

Hosting remains environment-configurable; no paid hosting requirement. Render free web services sleep after 15 idle minutes and free PostgreSQL expires after 30 days. A free deployment must document cold starts, database creation/expiry dates and a restore/migration plan covering the actual evaluation period; it cannot be called indefinitely available. See https://render.com/docs/free. Select a host/account only at deployment time with the owner; no automatic purchases or keep-alive workarounds.

Deployment verification pending: actual HTTPS cookie/logout, login-to-persisted-quote flow, API restart persistence, selected rate references, missing-rate error and readiness. Local real-browser login/reload/logout checks pass; session persistence across separate API/store instances is tested. HTTPS Secure-cookie behavior is tested with simulated trusted proxy headers. This is not a deployed quotation workflow. Login throttle uses process-local counters: one instance only; add a shared limiter before scaling. Expired session pruning runs periodically; no recovery, MFA or account-management screens in T01.
